The control plane for your app's LLM prompts

One prompt sets up everything. Prompt monitoring, evaluation, and deployment — all automatic.

Your coding AI checks whether PromptOn fits your app, installs it, moves every prompt and model call out of your codebase, and wires up monitoring. From then on, new models are evaluated on your real traffic and shipped with a pin. No code, no redeploy.

Paste this into your coding AI — Claude Code, Codex, Cursor, whatever you use.

It reads the guide, works out whether PromptOn fits, and walks you through the rest.

prompt.txt
Set up PromptOn for this app. Read __DOCS_URL__/agent first and
follow it step by step.

1. Tell me what PromptOn is: one line, a before-and-after code example, why
   it isn't a proxy, and what it automates (picking the model and prompt per
   use case, evaluating generations, catching drift).
2. Make sure you can see this project's code. If you can't, tell me to paste
   this into an AI that can, and stop. If you see several projects, ask which.
3. Check the fit: find every LLM call. PromptOn is for apps whose server calls
   LLM providers for several use cases, each with its own prompt and model.
   If that's not this app, say so and stop.
4. Install the CLI (curl -fsSL __HOME_URL__/install.sh | sh) and run
   `prompton login`. Walk me through signing up and approving it, then wait.
5. Write a migration plan from how our prompts are managed today. Wait for
   my OK.
6. Migrate in a new git worktree (ask me first if this isn't a git repo).
   Use the official PromptOn SDK for our language if there is one; otherwise
   follow the guide's client section. Keep our provider keys and HTTP calls.
   If PromptOn is ever unreachable, keep using the last snapshot you fetched.
7. Show me the diff.
What does it do? →

Not a proxy. Your app calls the model with your own keys; PromptOn hands it the prompt, the model, and the parameters. If we go down, your app keeps running on the last snapshot.

Here's what your agent does.

  1. 01

    Fit check

    The agent tells you what PromptOn is, makes sure it can see your code, and finds every LLM call. If PromptOn isn't right for your app, it says so and stops.

  2. 02

    Install & login

    The CLI installs in one line. We email you a six-digit code; you sign in, then approve the login. The agent waits while you do.

  3. 03

    Plan

    From however your prompts are managed today — hard-coded, config files, a database — the agent writes a migration plan. Nothing moves until you say OK.

  4. 04

    Migrate & diff

    The agent works in a new git worktree — a client it writes for your language, or our SDK where one exists. Your provider keys don't move. Nothing lands until you've read the diff.

A new model dropped. By lunch you know if it's better for your app.

  • Evaluate on real traffic Soon

    Score the new model against samples of your monitoring logs, with a rubric your coding AI writes from the few you rated.

  • Pin to staging

    One pin per environment: model, parameters, prompt version. No rules, no weights.

  • Promote or roll back

    Promote when you've looked. Every change is a revision; every revision rolls back in one click.

We're not in the request path.

  • Your keys stay yours.
  • If PromptOn is down, your app keeps running on the last snapshot.
  • Inputs and outputs are sampled and encrypted, with retention you set.

  • Deployments are pins

    One pin per environment. No router to debug at 2 a.m.

  • Prompts by name

    ko, default — with declared variables. A missing required one is a 400, never a silent fallback.

  • Side-by-side arena

    Run your real inputs through several models at once. History is kept per model.

  • Monitoring logs

    Tokens, cost, latency, stop reason — per use case, per environment.

  • Scoped API keys

    Per project: resolve, logs, or both.

  • Management API + CLI

    Everything in the UI is in the API. --json everywhere. Creates are idempotent.

  • Orgs and projects

    Personal and team organizations, members, usage.

  • Rollback in one click

    Every deployment is a revision you can return to.

Questions

Is this a proxy?
No. Your app calls the model provider directly with your own keys. PromptOn only serves configuration and receives logs.
What if PromptOn is down?
Your app keeps running on the last snapshot it fetched. Deploys pause; requests don't.
Which providers?
OpenRouter today, which covers most models. More are coming.
Is there an SDK for my language?
Elixir first; the rest are on the way. Until then your agent writes the client from the guide — a fetch, a cache, and a log call.
Do I have to use the CLI?
No. The web app does everything. The CLI and API exist so your coding AI can do it for you.
Where do my prompts live?
In PromptOn, on an encrypted database. Monitoring-log content and provider keys are additionally encrypted with a separate key. Export anytime.
